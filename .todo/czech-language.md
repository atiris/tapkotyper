# Czech as the third official language

## What and why

Czech becomes a full official language like Slovak and English: every game text (story, interface, help, tips, teacher pages, the about page), a Czech word list, the Czech keyboard layouts (QWERTZ and QWERTY) with their lesson order, tips that fit them, the voice for dictation, the about page `about/cs/` with its search metadata. Czech is the largest group of readers next to the Slovak audience, Czech schools teach ten-finger typing on the Czech QWERTZ layout, and today a Czech browser falls back to Slovak (`CLOSE` in `src/i18n/i18n.ts`), which a Czech child reads but cannot type: the Slovak layout has `ľ ť ä ô ň` where the Czech one has `ě ř ) ů ¨`.

Adding the language also proves the project's language seams. Today a third language would mean hunting `=== 'sk' ? … : …` across the code: the default layout per language is written out five times (`about-page.ts`, `new-profile.ts` twice, `translate.ts`, `store.ts`), the lesson order is a two-way ternary (`lessons.ts`), tips are filtered by a hard-coded "Slovak only" list and name Slovak keys in their text (`cards.ts`, `tips.*`), the parent's key presets are QWERTZ strings (`parent.ts`), the dictation rules are Slovak only (`words.ts heardSafe`), and the start-texts e2e loops `['sk', 'en']`. Step 1 turns each of these into one table keyed by language or layout, so the Czech rows of steps 2-5 are additions, not edits, and the next language costs the same.

Affected: `src/i18n/`, `src/keyboard/layouts.ts`, `src/learning/lessons.ts`, `src/game/cards.ts`, `src/words/words.ts`, `src/storage/schema.ts` + `store.ts` (types only: `Lang` and `LayoutId` gain members; no stored field changes, no migration, alpha), `src/screens/{new-profile,translate,help,parent}.ts`, `src/app/{about-page,app}.ts`, `public/i18n/cs.json`, `public/words/cs.json`, `public/sitemap.xml`, `e2e/start-texts.spec.ts`, specs in `.specify/experience/localization.md`, `.specify/learning/keyboard-layouts.md`, `.specify/learning/words.md`, README. No DB, no new dependency, no story or level change.

## Decisions

- **Codes.** Language `cs` (own name "Čeština"); layouts `cz-qwertz` (default for Czech, the Windows "Czech" layout, KBDCZ) and `cz-qwerty` (Windows "Czech (QWERTY)", KBDCZ1), the same pair as Slovak. The Czech Programmers layout is not offered. Short names `CZ QWERTZ` / `CZ QWERTY`.
- **Czech QWERTZ keys** (to be checked key by key against https://kbdlayout.info/kbdcz/ before writing them; the site is the reference, this list is the expectation): number row unshifted `; + ě š č ř ž ý á í é = ´`, shifted `° 1 2 3 4 5 6 7 8 9 0 % ˇ`; `BracketLeft` `ú` / `/`, `BracketRight` `)` / `(`, `Semicolon` `ů` / `"`, `Quote` `§` / `!`, `Backslash` dead diaeresis `¨` / `'`; letters, `Comma`, `Period`, `Slash` as on Slovak QWERTZ. Dead acute: `á é í ó ú ý` (+ capitals); dead caron: `č ď ě ň ř š ť ž` (+ capitals); `Ů` comes from the dead ring on Shift+`Backquote` if the reference confirms it, else from the key's real way. `cz-qwerty` swaps `Y`/`Z` like `sk-qwerty` (check KBDCZ1 for any other difference). Fingers follow the Slovak layout key by key (same physical keys), so the hands and the poser need nothing new.
- **Lesson order (`cz-qwertz`, `cz-qwerty`).** The Slovak path with Czech keys: home row `a` + `ů` (the right little finger's home key), then the same letters and punctuation in the same order; then the diacritics on their own keys `á í é ý ž ř č š ě ú`, then the dead-key letters `ď ť ň ó`, then digits. `)` and `¨` are not taught (Slovak `ä` and `ň` are taught because they are letters). World keys need no change: they are physical key names (`WORLD_KEYS` in `levels.ts`), filtered by what the layout's order teaches.
- **Tips by layout traits, texts with placeholders.** A tip is offered when the layout has what it talks about (dead keys, letters on the number row, `Y`/`Z` swapped against US), not by a list of Slovak tip ids. Tip texts that name keys take them from the layout through placeholders, as `homeRow.before` already does with `{f}` `{j}` `{left}` `{right}`: `tips.number-row` gets `{numberRow}` (the unshifted letters of the digit row), `tips.accent-pinky` `{pinkyKeys}` (the right little finger's letter keys beyond `p`/`l`), `tips.yz-swap` `{layout}`; `tips.diacritics-fun` says "these letters" instead of "Slovak letters" (en, sk, cs). `help.fingers` keeps naming Slovak keyboards in Slovak and English, and names Czech ones in Czech; `about.page.description` names the keyboards of all three languages in each language.
- **Dictation rules** per language as a table in `words.ts` (`heardSafe`): Czech uses the Slovak voicing rules (Czech voicing pairs `b-p d-t ď-ť g-k h-ch v-f z-s ž-š`, `ř` voiceless after a voiceless consonant counts as safe) and the same `i/y` rule after `b f l m p s v z`; it also drops words with `ů` or `ú` (the same sound), and `ě` after `b p v f m` (`bě` sounds like `bje`). English stays "always safe".
- **Word list.** `public/words/cs.json` is written by the session from its own knowledge of everyday Czech a 10-15-year-old reads: lower case, no proper names, nothing `BLOCK` matches (add Czech forms of the blocked roots to `BLOCK` if needed: `kurv`, `pič`, `hovn`, `sra`... already cover most), about the Slovak list's size (6 495) and the same shape (`{"words":[...]}`, the short home-row words first). No copied word list or corpus (licences). `words.test.ts` checks the first lessons' counts for `cz-qwertz` too; where a first lesson has too few Czech words, add real short words, never invented ones.
- **Texts.** `public/i18n/cs.json` is translated from Slovak (the closest source) with English as the meaning check, key by key, keeping every placeholder, `**bold**`, list length of ordered lines and pool sizes. Address "ty" for everyone (tykání), no gendered second-person past tense (rephrase: "Napsal jsi" -> "Máš napsáno"/present tense), terms "student" / "učitel", the app is "Ťapko" in Czech too (the same name, it reads naturally), the animal "postavička". World names stay at most 12 characters (Louka, Raketa, Planeta, Údolí, Vajíčko, Déšť, Město, Domov, Jezero). The translator page (`public/i18n/translator/en.json`) stays English, as its spec says; no `translator/cs.json`.
- **Detection.** `cs` is supported, so `CLOSE` loses `cs: 'sk'`; Slovak stays a supported language, so no new close pair is needed (`CLOSE` stays as a table, empty is fine).
- **Plural forms.** Czech has `one`, `few` (2-4), `many` (fractions) and `other`; every count in `cs.json` has the forms `Intl.PluralRules('cs')` uses, which match Slovak's.
- **About page and search.** `about/cs/` is built like the others (the `LANGS` loop in `vite.config.ts`), `og:locale` `cs_CZ`, hreflang `cs` in every page and in `public/sitemap.xml`. `index.html` stays Slovak (known exception: read before any language is known).
- **Review.** The owner reads the Czech texts in the game; the session does not wait for it. The final step adds a P2 backlog line "Czech texts and word list need a native read" only if the owner has not reviewed them by then.

Done 2026-11-15. Decisions: the reference was the Windows tables themselves (kbdlayout.info KLC downloads of KBDCZ and KBDCZ1): KBDCZ1 differs from KBDCZ only by Y/Z for everything the game draws, and both type the digits on Shift, so the capitals of the digit-row letters come through the dead keys as on Slovak.
